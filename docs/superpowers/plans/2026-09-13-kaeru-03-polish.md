# Kaeru — план 3: интерфейс уровня Netflix (минимальная, но полная комплектация)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers of UI tasks MUST load the `frontend-design:frontend-design` skill before writing Compose code.

**Goal:** Каждый экран телефона и ТВ выглядит и ведёт себя как продукт уровня Netflix/Crunchyroll: единая система дизайна, продуманные состояния (загрузка, пусто, ошибка), понятные подписи, ни одной «сырой» кнопки Material по умолчанию, все действия из спеки доступны и работают.

**Architecture:** Слой `ui.common.design` с токенами и библиотекой компонентов (карточки, hero, кнопки, шапки, состояния), на которой переписываются экраны `ui.mobile.*` и `ui.tv.*`. ViewModel-ы и домен не меняются, кроме добавления недостающих данных для UI (например, счётчики для табов, статус синка). Экран настроек появляется как новый маршрут.

**Tech Stack:** как в планах 1–2. Compose BOM 2025.08.01 (Compose 1.9: `SharedTransitionLayout` стабилен, `AnimatedVisibility`, `Crossfade`), Material 3 1.4, tv-material 1.1.0, Coil 3.3.0.

**Spec:** `docs/superpowers/specs/2026-09-12-kaeru-design.md`, раздел 9 («Интерфейс») — обязателен к прочтению каждым исполнителем; раздел 8 для экрана плеера.

## Design system (результат дизайн-прохода, обязателен для всех задач)

Субъект: приложение для одного действия — продолжить смотреть аниме. Аудитория: автор и друзья, вечер, диван, телефон в руке или пульт. Главная работа экрана: показать, что смотреть дальше, и запустить это одним касанием. Всё остальное — тихий фон.

**Палитра (закреплена спекой):** фон `#0B0C10`, поверхность `#15171E`, приподнятая `#1E212B`, разделитель `#2A2E3A`, текст `#F2F3F5`, вторичный текст `#9AA0AA`, акцент `#F5A524` (только «Смотреть», прогресс, фокус на ТВ, активный таб), на акценте `#1A1200`, ошибка `#E5484D`. Никаких других цветов. Контент (скриншоты и постеры) — главный «цвет» экрана.

**Типографика:** Manrope на всех весах через переменный шрифт (уже подключён). Шкала телефона: display 34/40 ExtraBold −0.8 (только заголовок hero), headline 24/30 Bold (названия экранов), title 17/22 SemiBold (названия карточек, кнопки), body 15/22 Regular (описания), label 13/18 SemiBold (метаданные: год, серии, озвучка). ТВ: ×1.35. Правила: без ALL CAPS, без «eyebrow»-подписей над заголовками, без разделителей «·» в метаданных — метаданные отдельными чипами или короткими фразами; предложение — с заглавной, остальное строчными.

**Сетка и форма:** 8dp; боковые отступы 16dp телефон, 56dp ТВ; постер 2:3 шириной 132dp телефон, 168dp ТВ; скругление карточек 12dp, кнопок 12dp, чипов 20dp; на ТВ фокус — масштаб 1.06 + рамка 3dp акцент, без свечения.

**Layout-концепция (телефон):**
```
┌─────────────────────────────┐
│ Kaeru            [cast][⚙︎] │  прозрачная шапка поверх backdrop
│ ┌─────────────────────────┐ │
│ │  backdrop (скриншот)     │ │  hero: 4:5, градиент снизу
│ │  Название                │ │
│ │  7 серия · осталось 14 мин│ │  (строка состояния — одна фраза, без точек-разделителей)
│ │  [▶ Смотреть]  [Подробнее]│ │
│ └─────────────────────────┘ │
│ Новые серии                  │  заголовок ряда title
│ [poster][poster][poster] →   │  карточки с бейджем «7 серия» и полоской прогресса
│ Продолжить                   │
│ ...                          │
├─────────────────────────────┤
│  Главная   Мой список  Поиск │  нижняя панель, активный — акцент
└─────────────────────────────┘
```
Выравнивание — по левому краю везде; центрирование только для пустых состояний.

**Копирайт:** глаголы в кнопках говорят, что произойдёт: «Смотреть 7 серию», «Продолжить с 14:20», «Добавить в планы», «Выйти из аккаунта». Ошибки объясняют причину и следующий шаг: «Нет соединения. Проверьте интернет и повторите», кнопка «Повторить». Пустые состояния приглашают: «Здесь появятся тайтлы из списка «Смотрю». Найти аниме →» (без стрелки в тексте — стрелка запрещена, кнопка «Найти аниме»).

**Движение:** одно оркестрованное появление — hero проявляется кроссфейдом при смене верхнего элемента; shared-element постер → экран тайтла; всё остальное без анимаций входа. Реакция на действие — всегда (нажатие кнопки, раскрытие описания, смена статуса).

**Проверка против шаблонных дефолтов:** палитра «почти чёрный + один яркий акцент» задана спекой, поэтому принимается; свободные оси потрачены не на дефолты: типографика без капса и eyebrow, метаданные без «·», карточки только двух видов (постер и hero), тени отсутствуют (глубина через фон и градиенты), декоративных градиентов нет — только функциональные скримы над изображениями.

## Global Constraints

- Всё из планов 1–2 (пакеты, версии, слои `ui.* → domain/player`, тексты ошибок через `toUserMessage()`).
- Ни одного `Button(onClick){ Text("…") }` со стандартным стилем в экранах: только компоненты из `ui.common.design`.
- Каждый экран имеет три состояния (загрузка — скелетоны, пусто — приглашение с действием, ошибка — причина + «Повторить») и не показывает крутилку дольше 300 мс без скелетона.
- Все тап-цели ≥ 48dp; на ТВ каждый фокусируемый элемент имеет видимый фокус; `contentDescription` у всех иконок.
- Ни одной строки на русском в коде ViewModel/домена — тексты только в UI (пока без `strings.xml`, допускаются константы в файлах экранов).
- Проверка каждой задачи: unit-тесты зелёные + `assembleDebug` + скриншоты экранов с телефона (`adb exec-out screencap`) приложены в отчёт, если устройство подключено; без устройства — превью `@Preview` для каждого нового компонента.

Тест: чистые функции форматирования подписей (`episodeLine`, `remainingLine`, `episodesLabel`) — перенести/дополнить из `ui.common.Format`.

### Task 2: Главная телефона
Переписать `HomeScreen` на компоненты: прозрачная шапка (логотип-текст «Kaeru», кнопка каста, настройки), hero 4:5 с backdrop и двумя кнопками, ряды `Новые серии / Продолжить / Дальше по списку / Скоро / В планах` с бейджами и прогрессом, pull-to-refresh, скелетоны, пустое состояние с «Найти аниме», ошибка через snackbar с «Повторить». Hero кроссфейд при смене top-элемента. Нижняя панель: акцентный активный пункт, подписи title-стилем.

### Task 2b: Открытия на главной — «Популярно сейчас» и «Популярное в сезоне»
Два ряда ниже персональных: «Популярно сейчас» (Shikimori `GET /api/animes?status=ongoing&order=popularity&limit=20`) и «Популярное в сезоне» с переключателем сезонов (чипы: текущий сезон, предыдущий, следующий; `GET /api/animes?season=summer_2026&order=popularity&limit=20`; сезоны по правилам Shikimori: winter/spring/summer/fall + год). Данные вне списка пользователя: новый `DiscoverRepository` (domain-интерфейс + реализация в `data`) с кэшем в памяти на 6 часов и обновлением по pull-to-refresh; постеры через тот же GraphQL-фолбэк, что и списки. Карточки открывают экран тайтла (для тайтлов вне списка там уже есть «Добавить в планы»). Пустые/ошибочные состояния рядов — тихие: ряд скрывается при ошибке и показывает скелетон при загрузке. Чистая функция выбора сезонов с тестами; `HomeUiState` получает `discover` блок.

### Task 4: Мой список и Поиск
Табы со счётчиками, сортировка (обновление / название) как сегментированный контрол, сетка `PosterCard`, пустые табы с текстом-приглашением; поиск: поле с иконкой и очисткой, недавние запросы горизонтальным скроллом чипов, результаты карточками с «Добавить в планы» → «В списке», состояние «ничего не найдено» с подсказкой, ошибка с «Повторить».

### Task 4b: Память озвучек
Аниме уже запоминает озвучку последнего просмотра (`WatchState.translationId`, правило 1 `TranslationRanker`); новое аниме должно предлагать озвучки в порядке того, как часто зритель их выбирает. Данные: `WatchStateRepository.observeAll(): Flow<List<WatchState>>` (DAO `observeAll` уже есть) и чистая функция `TranslationUsage.of(states: List<WatchState>): Map<Int, Int>` — translationId → число аниме, только ненулевые id. Ранжирование `TranslationRanker.sort/pick(available, preferred, rememberedId, usage)`: запомненная для этого аниме → студии из списка, заданного пользователем в настройках → частота использования по убыванию → встроенный список студий по умолчанию (`TranslationRanker.DEFAULT_STUDIOS`, переезжает из `AppPreferences.DEFAULT_PREFERRED_TRANSLATIONS`) → озвучка перед субтитрами → число серий → порядок источника. `PlaybackPreferences.preferredTranslations` отдаёт только пользовательский список (пустой, если не задан); `ResolveEpisodeStream` берёт usage из `observeAll().first()` и для `pick`, и для `translations`. UI: в `TranslationPicker` (тайтл), `TranslationSheet` (плеер) и ТВ-диалоге подпись «Часто выбираете» у дорожек с usage ≥ 2, когда у аниме нет запомненной озвучки; порядок списка — из `translations`. Тесты: `TranslationUsage`, порядок ранжирования (запомненная > пользовательский список > частота > список по умолчанию), `ResolveEpisodeStream` выбирает самую частую озвучку для нового аниме, отсутствие ключа в `AppPreferences` → пустой список.

### Task 5: Плеер телефона
Полноэкранный тёмный плеер: верх — название и «7 серия», кнопки озвучки/качества/каста; центр — play/pause и ±10 с; низ — таймлайн с буфером и таймкодами, «+85 с», «Следующая серия»; автоскрытие 3 с; двойной тап с индикатором ±10; свайпы яркости/громкости с индикатором; карточка следующей серии за 30 с; листы выбора озвучки (сортировка из `TranslationRanker.sort`, отметка текущей) и качества; диалог «Перевести в завершённые?»; ошибки с «Повторить» и «Сменить озвучку». Режим пульта при касте.

Картинка в картинке (PiP): `PlayerActivity` объявляет `supportsPictureInPicture="true"`; при нажатии Home или свайпе домой во время воспроизведения плеер сворачивается в PiP (`setAutoEnterEnabled` на API 31+, `enterPictureInPictureMode` с соотношением сторон видео на API 26–30 в `onUserLeaveHint`); в PiP контролы скрыты, доступны системные действия play/pause и «следующая серия» через `RemoteAction`; прогресс и отметка серии продолжают работать; при раскрытии окна возвращается полноэкранный плеер; при закрытии PiP — пауза и сохранение позиции. Кнопка «В окно» в контролах для ручного входа в PiP.

Долги плана 2, закрываемые в этой задаче: список серий на экране пульта при касте (спека §8), свайпы яркости/громкости (спека §8), медиа-уведомление во время каста, фиксация выбранного качества в настройках по желанию пользователя, ограничение главной кнопки тайтла вышедшими сериями, страховка от «пустого» списка озвучек у фильмов без блока озвучек.

Таймлайн — собственный `KaeruSeekBar` на `Canvas`, а не поверх M3 `Slider` (пользователь видит ползунок «чуть кривым» на сборке d09257f): трек 4 dp, буфер, проигранное акцентом и бегунок 14 dp (18 dp при перетаскивании) рисуются одним `drawBehind`, размер бегунка не влияет на разметку; отступ трека слева и справа равен отступу строки таймкодов, бегунок нависает над концами трека; тап ставит позицию, горизонтальное перетаскивание ведёт бегунок (`pointerInput`), контракт `onScrub`/`onScrubEnd` сохраняется; новый параметр `buffered: Float = 0f`; семантика `progressBarRangeInfo` и `setProgress`; чистая функция `seekFraction(x: Float, width: Float, inset: Float): Float` с тестами; превью 0 %, 42 %, 93 % и disabled.

### Task 5d: Прогресс по сериям
Сейчас у аниме одна «текущая» позиция (`WatchState`: серия + позиция), и случайный переход на более раннюю серию затирает прогресс более поздней (пользователь: «при переходе серии назад, если я мискликнул, не сохраняется серия предыдущая»). Решение: позиции хранятся по каждой серии — новая таблица `episode_progress` (animeId, episode, positionMs, durationMs, updatedAt; ключ animeId+episode; Room миграция 2→3 явная, без разрушительного фолбэка), а `WatchState` остаётся памятью озвучки/сезона и указателем на последнюю игравшую серию. «Продолжить» становится чистой функцией `ContinueTarget.of(rate, progress: List<EpisodeProgress>, threshold, now)`: самая старшая серия с незавершённым прогрессом (позиция ≥ 60 с или ≥ 2 % длительности и меньше порога просмотра), иначе `rate.episodes + 1`, но не выше вышедших; серии, у которых прогресс меньше этой отсечки, считаются не начатыми (мисклик), и указатель на них не переносится. Сэмплер `WatchProgress` пишет в `episode_progress` по серии; отметка «просмотрено» по порогу — как раньше. Экран тайтла и ТВ‑сетка показывают полоску прогресса на каждой начатой серии, не только на текущей; главная и «Продолжить с 14:20» берут позицию из целевой серии. Тесты: `ContinueTarget` (мисклик на 6‑ю не двигает указатель с 7‑й; досмотренная 7‑я → 8‑я; ничего не начато → `rate.episodes + 1`; невышедшие не предлагаются), миграция (round trip DAO), `HomeFeedBuilder`/`primaryAction` с новыми входами, `EpisodeGrid` полоски.

### Task 7: Android TV
Вход по QR без ввода кода: ТВ показывает QR `kaeru://pair?host&port&nonce&name` и поднимает локальный одноэндпоинтовый HTTP-сервер (nonce живёт 5 мин); телефон с Kaeru открывает deep link, показывает «Войти на телевизоре „<имя>"?», после подтверждения получает свежий код авторизации Shikimori через свою сессию и отправляет `{code, nonce}` ТВ по локальной сети; ТВ обменивает код на токены штатным OAuth. В сеть уходит только одноразовый код. Ввод кода вручную остаётся запасным путём под QR. Экран входа ТВ переделывается под дизайн-систему и новый масштаб шрифтов.
Drawer-навигация (Главная, Мой список, Поиск, Настройки), immersive-главная: backdrop кроссфейд по фокусу, hero-текст, ряды `PosterCard`-ТВ; экран тайтла двумя колонками (постер + кнопки + описание | сетка серий); поиск с сеткой; настройки ТВ (озвучки, автовоспроизведение, выход с подтверждением); плеер ТВ с панелью по любой кнопке. Возврат из тайтла сохраняет позицию скролла и фокус.
