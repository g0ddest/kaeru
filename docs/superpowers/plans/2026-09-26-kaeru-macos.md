## Global Constraints

- macOS **15.0** minimum, **arm64 only** (`ARCHS = arm64`; `macosX64` is deprecated in Kotlin 2.3.21).
- Bundle id `app.kaeru.mac`, team `TXY49DW96F`, product name `Kaeru`. App Sandbox **on** with
  `network.client`, `network.server`, `device.audio-input`; hardened runtime on.
- iOS stays as it is: after every task `ruby ios/App/generate_project.rb`, the iOS app builds for the simulator
  and the iOS unit tests pass (commands in memory: `xcodebuild -project ios/App/Kaeru.xcodeproj -scheme Kaeru
  -destination 'platform=iOS Simulator,id=E88C5504-56A1-491D-B2E5-C8091376F239' -derivedDataPath <scratch> build test`,
  `JAVA_HOME` = JDK 21, `ANDROID_HOME` set). Android is untouched (`./gradlew :android:testDebugUnitTest` stays green
  if `shared/` or Gradle files change).
- Swift 6 strict concurrency `complete`, no new warnings. Platform splits use `#if os(macOS)` / `#if os(iOS)`;
  prefer one cross-platform shim (`Compat.swift`) over scattering conditions.
- Chromecast, QR camera scanning and «PiP при выходе» do not exist on macOS (no-op cast transport, hidden UI).
- Never commit `Configuration.plist`, `GoogleService-Info.plist`, the generated `.xcodeproj`, or `Dependencies/`.
- Commits in Russian (`feat(mac): …`, `fix(mac): …`). No push, no release, no gh-pages publish inside tasks.

## Review Focus

1. **Data location.** SwiftData store, downloads and caches live in the app's sandbox container — never in shared
   `~/Library/Application Support/default.store` (`LocalStore.discardingCache()` would delete another app's file).
2. **Keys vs text fields.** Player shortcuts (Space, ←/→, F, M, N) must not fire while the together chat field or
   the search field has focus.
3. **iOS regressions.** Every shim keeps the exact iOS behaviour (same modifiers, same presentation).
4. **Sign-in on Mac.** `ASWebAuthenticationSession` gets a real window anchor; the `kaeru://oauth` callback works.
5. **Player window lifecycle.** Closing the player window stops playback, saves the position and allows a new
   player; only one player at a time (`playersOpen`).

### Task 2: the KaeruMac target in the generator

Maps: `2-build.md` §generator, §icon, §Firebase; `1-code.md` §Info.plist/entitlements. In `generate_project.rb` add
application target `KaeruMac` (`:osx`, `15.0`, `PRODUCT_NAME = Kaeru`, bundle id above, `ARCHS = arm64`,
`MACOSX_DEPLOYMENT_TARGET = 15.0`, automatic signing, `ENABLE_HARDENED_RUNTIME = YES`), its own
`ios/App/Mac/Info.plist` (with `NSApplicationCrashOnExceptions`, `NSMicrophoneUsageDescription` copy from iOS,
`kaeru` URL scheme, `LSApplicationCategoryType = public.app-category.entertainment`) and
`ios/App/Mac/Kaeru.entitlements` (sandbox set above; `applinks:kaeru.vitaliy.velikodniy.name` only when
`MAC_ASSOCIATED_DOMAINS=1`, default off until a Developer ID profile exists). Sources = the iOS app's minus
iOS-only files (Cast transport, QR scanner, iOS app delegate…); the KaeruShared script phase and search paths
shared; GoogleCast and GTMSessionFetcher linked only to the iOS target; Firebase products added to the Mac target
only when `ios/App/Mac/GoogleService-Info.plist` exists (own dSYM phase). App icon: add the `mac` idiom sizes to the
asset catalog from a new rounded-square master rendered by a small script from the existing 1024 icon (keep the
script in `ios/Scripts/`). A scheme `KaeruMac`. At this task's end the Mac target may not compile yet — the task is
done when the project generates, iOS builds and tests pass, and `xcodebuild -scheme KaeruMac -showBuildSettings`
shows the settings above. Commit `feat(mac): цель KaeruMac в генераторе проекта`.

### Task 3: the code compiles and runs on macOS

### Task 4: Mac-native presentation and controls

Maps: `3-ux.md` (scenes, player, menus, keys, hover, v1 scope). Scenes: main `WindowGroup` (min 900×600, default
1280×820, no ⌘N), a player `Window` (1280×720, min 640×360, not restored at launch) replacing the iOS full-screen
covers through one `playerPresentation` modifier, and a `Settings` scene (⌘,) with the existing settings form.
Player: click toggles play/pause, controls and cursor hide after 3 s idle, window full screen (F, ⌃⌘F,
double-click), a **Воспроизведение** menu with Space, ←/→ (skip seconds), F, M, N, Esc — disabled while a text field
has focus (Review Focus 2); media keys via the remote command center. Closing the player window stops playback and
saves the position (Review Focus 5). Browsing: hover highlight on cards/rows/chips, `.help` tooltips, context menus on
search results and episode cards, a Mac pager for the hero, **Обновить** (⌘R) where iOS uses pull-to-refresh, minimum
sizes for sheets, the together join screen as a sheet and «Пригласить» copying the link. Unit-test the key routing
(pure function: key + focus state → action) the way `web/src/player/keys.ts` does. Verify with screenshots of: main
window, a title page, the player playing a real episode (catalogue and Kodik work without sign-in), the player in
full screen, the Settings window. Commit(s) `feat(mac): окна, меню и управление по-маковски`.

### Task 5: updates, universal links, release script

Maps: `2-build.md` §distribution, `1-code.md` §Update. The Update module on macOS picks the `.dmg` asset of a GitHub
release and opens it in the browser (unit test for the asset choice). `docs/cast/.well-known/apple-app-site-association`
gains `TXY49DW96F.app.kaeru.mac` beside the iOS id (same paths), and `android/.../AssetLinksTest` or any test that
reads that file still passes. `ios/Scripts/release-mac.sh`: archive → export `developer-id` → `hdiutil` UDZO dmg →
`codesign` the dmg → `xcrun notarytool submit --keychain-profile kaeru-notary --wait` → `xcrun stapler staple`;
it stops with a clear Russian message when the Developer ID certificate or the notary profile is missing
(`--dry-run` builds and exports up to the first missing piece). `ios/README.md` gets a «macOS» section: build, run,
release, and the two one-time steps for the owner. Commit `feat(mac): обновления через .dmg, ссылки и скрипт выпуска`.
