# Kaeru foundation — ручная приёмка

Дата: 2026-09-12

Ручная приёмка выполнялась без физического устройства и без эмулятора
(`adb devices` — пустой список). Автоматическая проверка (сборка, unit-тесты,
lint, сборка APK, проверка манифеста и секретов) выполнена и зафиксирована в
`.superpowers/sdd/2026-09-12-kaeru-01-foundation/task-12-report.md`. Пункты,
требующие устройства, живого Shikimori-аккаунта или запуска плеера/каста,
оставлены неотмеченными и ждут прогона на реальном устройстве — они не
проверялись, а не проверялись и провалились.

## Spike Kodik / Chromecast

- [x] Токен извлечён или причина отказа записана в design spec
- [ ] HLS manifest и первый segment отвечают HTTP 200
- [ ] CORS-заголовок записан в design spec
- [ ] ffprobe видит H.264 + AAC
- [ ] Default Media Receiver воспроизводит серию либо CAF отмечен обязательным

Примечание: spike (Task 1, 2026-09-12) остановился до получения HLS-ссылки —
публичный токен, извлечённый из `add-players.min.js?v=2`, был отклонён
`kodik-api.com/search` с ошибкой «Отсутствует или неверный токен». Причина
отказа зафиксирована в
`docs/superpowers/specs/2026-09-12-kaeru-design.md` (раздел «Риск и первый
spike»), поэтому первый пункт отмечен. HLS manifest, CORS, ffprobe и Default
Media Receiver не проверялись, так как резолв не дошёл до этого шага;
`tools/fixtures/` с этого spike не создавались. Риск Default Media Receiver
остаётся открытым: план 2 обязан рассматривать собственный CAF receiver как
обязательный, а не резервный, пока успешный повторный spike не закроет риск.

## Shikimori

- [ ] `User-Agent: Kaeru/0.1.0` присутствует
- [ ] Один refresh token request обслуживает параллельные 401
- [ ] Повторный запуск читает сохранённую сессию

Примечание: ни один пункт не проверен — проверка требует живого OAuth-обмена

поведение покрыто unit- и integration-тестами (см. `:app:testDebugUnitTest`),
но это не заменяет ручную проверку на реальном аккаунте.
