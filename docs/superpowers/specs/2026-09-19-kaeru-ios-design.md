# Kaeru iOS — дизайн нативного приложения

Дата: 2026-09-19  
Статус: согласовано для планирования  
Ветка: `feat/ios-native-app`

## 1. Цель

Добавить в репозиторий нативное приложение Kaeru для iPhone и iPad. Первая
версия должна позволять войти через Shikimori, открыть главную, библиотеку и
поиск, перейти на экран тайтла и запустить нужную серию через Kodik. Прогресс
внутри серии и отметки просмотренных эпизодов должны синхронизироваться с
Shikimori так же, как в Android-приложении.

Интерфейс строится на SwiftUI и системных iOS-компонентах. Визуальное
направление — media-first и тёмное, с крупными обложками, плавным переходом к
плееру и поведением, знакомым по iMovie. Это не копия iMovie: навигация,
доступность и системные жесты остаются стандартными для iOS.

Первая версия поддерживает iOS 17 и новее, iPhone в compact width и iPad в
regular width, включая split screen и Stage Manager.

## 2. Объём первой версии

Входит:

- OAuth2-вход в Shikimori через `ASWebAuthenticationSession` и redirect
  `kaeru://oauth`;
- главная из локального кэша с секциями «Продолжить», «Новые серии», «Скоро»
  и «В планах»;
- библиотека с фильтрами по статусу и сортировкой;
- поиск аниме через Shikimori, история недавних запросов и добавление в планы;
- экран тайтла с постером, описанием, статусом, эпизодами, прогрессом и выбором
  озвучки;
- резолв потока Kodik через `get-player` → страницу плеера → `/ftor`;
- нативное воспроизведение HLS через AVFoundation/AVPlayer;
- перемотка, пауза, продолжение с позиции, смена качества и озвучки;
- сохранение локального прогресса и отправка отметок просмотра в Shikimori;
- адаптивный интерфейс iPhone/iPad, Dynamic Type, VoiceOver и системные
  safe areas.

Не входит в первую версию:

- офлайн-загрузки и воспроизведение загруженных серий;
- Watch Together;
- Chromecast и AirPlay-специфичная логика приложения;
- локальные уведомления о новых сериях;
- Android TV и общий UI между платформами;
- светлая тема.

Эти возможности остаются следующими отдельными этапами после проверки
основного iOS-пути.

## 3. Критерии успеха

- Чистая сборка открывает приложение на iPhone и iPad без Android-зависимостей
  в `ios/`.
- Авторизация создаёт сессию и сохраняет токены в Keychain.
- Повторный запуск показывает кэшированную главную, если сеть временно
  недоступна.
- Из карточки «Продолжить» можно одним нажатием открыть нужный эпизод.
- Kodik-цепочка проходит на `URLSession`/Ktor без `WKWebView`; это подтверждено
  iOS spike report от 2026-09-19.
- AVPlayer играет HLS, сохраняет позицию, позволяет перемотать и сменить
  качество без сброса на начало.
- Изменение качества создаёт новый `AVPlayerItem` и восстанавливает позицию,
  потому что Kodik отдаёт отдельный VOD-манифест на каждое качество, а не
  master-playlist.
- Один и тот же feature flow работает в portrait и landscape на iPhone и в
  regular/compact ширинах на iPad.
- Ошибки сети, пустые данные, устаревшая ссылка Kodik и ошибка парсера имеют
  понятное состояние с повтором или возвратом к списку серий.

## 4. Репозиторий и границы модулей

Первые изменения находятся в корне репозитория и не требуют переноса текущего
Android-кода:

```text
ios/
  App/
  Features/
    Auth/
    Home/
    Library/
    Search/
    Details/
    Settings/
  Player/
  Services/
  DesignSystem/
  Tests/

shared/
  build.gradle.kts
  src/commonMain/kotlin/app/kaeru/shared/
    domain/
    data/kodik/
    data/shikimori/
    data/auth/
    data/playback/
  src/commonTest/kotlin/app/kaeru/shared/
  src/androidMain/kotlin/app/kaeru/shared/
  src/iosMain/kotlin/app/kaeru/shared/
```

`ios/` содержит только нативный SwiftUI-продукт и iOS-интеграции. Он не
подключает Android UI, Media3 или Hilt.

`shared` содержит переносимую бизнес-логику:

- доменные модели и интерфейсы репозиториев;
- чистые правила home feed, выбора озвучки, качества и следующего эпизода;
- Kodik token provider, API, HTML parser и ROT+base64 decoder;
- Shikimori DTO, API-мэппинг, rate limit и OAuth-сценарий;
- use cases для каталога, библиотеки, поиска, прогресса и отметки просмотра;
- контракты для локального состояния и часов.

`shared` не знает о SwiftUI, Compose, AVPlayer, UIKit, Hilt или Android Context.
Платформенная реализация хранилища токенов и локальных данных подключается
через интерфейсы:

- iOS: Keychain и SwiftData-адаптер;
- Android: существующие DataStore и Room-адаптеры до отдельной миграции.

Нативный iOS-плеер не проталкивается в `shared`. Общий слой возвращает
`EpisodeStream` с URL, заголовками, качествами и временем резолва; `ios/Player`
создаёт AVURLAsset и управляет AVPlayer.

## 5. Общая архитектура данных

```text
SwiftUI view
  → feature model (@Observable)
  → shared use case
  → repository interface
  → Ktor / Shikimori / Kodik
  → domain state
  → feature model
  → SwiftUI
```

Каждый feature имеет собственную модель состояния и не вызывает сетевой клиент
из View. Минимальные границы:

- `HomeFeatureModel` вызывает `GetHomeFeed` и `SyncUserLists`;
- `LibraryFeatureModel` вызывает получение локальных `UserRate` и изменение
  статуса;
- `SearchFeatureModel` вызывает `SearchAnime` и `ChangeListStatus`;
- `DetailsFeatureModel` вызывает `GetAnimeDetails`, `translations` и
  `ResolveEpisodeStream` только при запуске серии;
- `PlayerFeatureModel` получает `EpisodeStream`, передаёт его
  `PlaybackCoordinator`, принимает события позиции и вызывает
  `ReportPlaybackProgress`/`MarkEpisodeWatched`.

Сетевые запросы выполняются через общий Ktor-клиент. На iOS используется
`ktor-client-darwin`; cookies не являются частью контракта Kodik. Редиректы
обрабатываются клиентом, а ссылки Kodik всегда резолвятся непосредственно на
устройстве воспроизведения.

## 6. Авторизация и локальные данные

OAuth-поток:

1. Пользователь нажимает «Войти».
2. `ASWebAuthenticationSession` открывает авторизацию Shikimori.
3. Redirect `kaeru://oauth` возвращает authorization code.
4. Shared auth use case обменивает code на токены через существующий OAuth
   контракт проекта.
5. `KeychainTokenStore` сохраняет access/refresh token.
6. При старте `AccountSession` проверяет токен, обновляет его при необходимости
   и загружает локальный кэш.

Client secret не хранится в iOS bundle. Конфигурация клиента и уже принятый в
репозитории OAuth proxy остаются источником истины.

В iOS локально сохраняются:

- кэш аниме и user rates;
- состояние просмотра по серии: позиция, длительность, озвучка, качество и
  время изменения;
- очередь неподтверждённых отметок Shikimori;
- пользовательские настройки озвучки, качества и автоперехода;
- недавние поисковые запросы.

SwiftData используется только как iOS-адаптер хранения. Доменные модели и
правила конфликтов остаются в `shared`; при восстановлении сети очередь
повторяет записи с экспоненциальной паузой, а конфликт эпизодов разрешается
большим значением просмотренных серий.

## 7. Навигация и UX

### iPhone

Корневой `TabView` содержит три вкладки:

- «Главная» — продолжение просмотра и рекомендации;
- «Мой список» — статусы Shikimori и сетка постеров;
- «Поиск» — поиск и результаты.

Настройки открываются из toolbar главной и библиотеки. Детали тайтла и экран
поискового результата открываются в `NavigationStack`. Плеер открывается как
полноэкранный cover и может переходить в системный PiP на следующем этапе.

### iPad

Корневой контейнер использует `NavigationSplitView`:

- в sidebar находятся те же три раздела и настройки;
- в regular width список и выбранный тайтл могут быть видны одновременно;
- при compact width поведение автоматически становится таким же, как на
  iPhone;
- player занимает отдельный detail/full-screen слой и не ломает back stack.

### Визуальный язык

- только тёмная тема;
- фон `#0B0C10`, поверхности `#15171E` и `#1E212B`;
- основной текст `#F2F3F5`, вторичный `#9AA0AA`;
- янтарный акцент `#F5A524` для primary action и прогресса;
- крупные poster/backdrop изображения, градиентная маска и скругление 12pt;
- системные `Button`, `Toolbar`, `Sheet`, `NavigationStack`, `List` и SF
  Symbols вместо самодельных навигационных компонентов;
- анимации короткие и отключаются при Reduce Motion.

Главная использует верхнюю карточку «Продолжить» или «Новые серии». Она не
перегружена контентом: один главный action ведёт к воспроизведению, вторичный
открывает тайтл. Горизонтальные секции используют native horizontal scrolling
с крупными poster cards.

Экран тайтла содержит hero, кнопку «Продолжить N серию» или «Смотреть 1
серию», смену статуса, выбор озвучки и список серий. Описание сворачивается,
чтобы список эпизодов оставался доступным без длинного прокручивания.

## 8. Нативный плеер

`PlaybackCoordinator` в `ios/Player` владеет AVPlayer и предоставляет модели
состояния SwiftUI. Для вывода видео используется `AVPlayerViewController`
через тонкую SwiftUI-обёртку; кастомные overlay controls располагаются поверх
него. Это сохраняет системную обработку аудио, внешних устройств и будущего
PiP.

При запуске:

1. `PlayerFeatureModel` получает локальную позицию и выбранную озвучку.
2. Shared `ResolveEpisodeStream` получает свежие подписанные URL Kodik.
3. `PlaybackCoordinator` создаёт `AVURLAsset` с
   `AVURLAssetHTTPHeaderFieldsKey` и передаёт его `AVPlayerItem`.
4. При готовности item восстанавливается позиция и запускается playback.
5. Позиция сохраняется каждые 5 секунд, при паузе и при закрытии плеера.

Заголовки `Referer`, `Origin`, `User-Agent` и диагностический произвольный
заголовок были измерены на iOS 26.5 и доходят до плейлиста и сегментов. В
обычном пути они не требуются Kodik, но остаются в конфигурации для устойчивости
к будущей проверке источника.

Kodik отдаёт отдельные VOD-плейлисты для 360p/480p/720p. Поэтому смена
качества создаёт новый item, запоминает текущую позицию, загружает новый поток
и делает seek после `status == .readyToPlay`. Плеер не заявляет adaptive bitrate
там, где его нет в исходном манифесте.

Ошибка истёкшей ссылки вызывает один повторный resolve, затем показывает
«Ссылка устарела, попробуйте ещё раз». `ParserBroken` показывает сообщение об
обновлении источника и не маскируется под сетевой сбой.

## 9. Состояния и ошибки

Каждый feature имеет состояния loading, content, empty и error. Loading
показывается скелетоном, а не бесконечным spinner. Ошибка содержит короткое
сообщение, действие «Повторить» и, если возможно, переход к локальным данным.

Основные ошибки:

- нет аккаунта — экран входа;
- нет сети — кэшированные данные остаются доступными, сетевые действия
  предлагают повторить позже;
- Shikimori rate limit — задержка и повтор через общий rate limiter;
- Kodik не нашёл серию — экран тайтла остаётся доступным, запуск следующей
  серии не блокируется;
- ошибка парсера — отдельный `ParserBroken(step)` с повтором и сообщением об
  обновлении приложения;
- пустая библиотека — явная кнопка «Найти аниме»;
- отсутствующая озвучка — список доступных озвучек с выбором другой.

## 10. Тестирование и ручная проверка

`shared` покрывается существующими Kotlin-тестами и новыми multiplatform
тестами:

- Kodik HTML parser и link decoder на сохранённых фикстурах;
- токен provider: кэш, истечение и повтор после 401;
- Shikimori mapping, rate limit и OAuth refresh;
- home feed, ранжирование озвучки, выбор качества и следующей серии;
- очередь прогресса и конфликт больших значений `episodes`.

`ios/` покрывается XCTest:

- feature model для loading/content/error и retry;
- deep link `kaeru://oauth`;
- Keychain adapter через тестовый service account;
- восстановление позиции при смене качества;
- обработка истёкшей Kodik-ссылки;
- компактная и regular навигация через UI tests для главных маршрутов.

Перед первой iOS-вехой выполняется ручная матрица:

- iPhone simulator: portrait, landscape в player, холодный и тёплый старт;
- iPad simulator: full screen, split screen, Stage Manager и rotation;
- физический iPhone: OAuth, Kodik, звук, background audio и длительное
  воспроизведение;
- физический iPad: навигация, keyboard search, player и восстановление позиции;
- Shikimori: изменение статуса и отметка просмотра после выхода из плеера.

## 11. Порядок реализации

1. Зафиксировать `ios/` и `shared/` как корневые merge-friendly директории.
2. Создать минимальный KMP `shared` и нативный SwiftUI app target, который
   собирается на iPhone/iPad simulator.
3. Перенести в `shared` чистые доменные модели, Kodik parser/decoder и
   Shikimori contracts, сохранив Android baseline зелёным.
4. Подключить iOS OAuth, Keychain, SwiftData и кэшированную главную.
5. Реализовать библиотеку, поиск и экран тайтла.
6. Подключить свежий Kodik resolve и локальный AVPlayer.
7. Добавить прогресс, смену качества/озвучки и синхронизацию с Shikimori.
8. Провести iPhone/iPad ручную проверку, accessibility pass и подготовить
   отдельные design-system previews.
9. После закрытия первой версии спланировать офлайн-загрузки отдельным
   design/plan циклом.

Каждый крупный этап заканчивается отдельным небольшим коммитом. Android
переключается на `shared` постепенно; первоначальная iOS-ветка не переносит
существующие Android-файлы и не меняет их интерфейс без теста на регрессию.
